# Просмотрщик «Граф денег»

Локальное рабочее место аналитика. Показывает очередь счетов для проверки, кластеры, направленные связи
выбранного счёта и основания для гипотезы о его роли. Все цифры берутся из `out/analysis.json`, который
создаёт конвейер; интерфейс ничего не вычисляет заново и не отправляет запросов во внешнюю сеть.

## Запуск

Нужен Node.js `^20.19` или `>=22.12` (требование Vite 7). Первая установка зависимостей обращается к
реестру npm; после сборки приложение работает без сети.

```bash
cd web
npm ci
npm run build          # проверка типов и сборка в web/dist/
```

Собранный `web/dist/` вместе с `out/analysis.json` отдаёт корневой `serve.py` (команда `./run.sh`).
Для разработки:

```bash
WORKBENCH_OUT=../out npm run dev     # настоящий out/analysis.json
npm run dev:fixture                  # синтетический пример из web/fixtures/
npm test                             # проверки логики (vitest)
WORKBENCH_REAL=../out/analysis.json npm test   # те же проверки на настоящем файле
```

Сервер разработки отдаёт по адресу `/out/` только `analysis.json` и три CSV-файла из указанного каталога.

## Что умеет экран

- Очередь проверки (`top_nodes`) и список кластеров с гипотезами.
- Поиск по точному `gid`. Счёт открывается только при полном совпадении строки цифр. Частичное совпадение
  предлагается списком. Соседнее число (например, `gid + 1`) сообщает «не найден» и не подменяет счёт.
  Ссылка `#gid=…&mode=…` открывает счёт напрямую.
- Направленная окрестность на один шаг: плательщики сверху, получатели снизу, встречные потоки по бокам.
  Циклы через счёт показаны как «возвратный поток». После 10 карточек сторона сворачивается в карточку
  «ещё N · сумма», которая ведёт в полный список. Вид «Список» — доступная таблица всех связей с датами.
- Основания: роль и опора правила, само правило с порогами, ближайшая альтернатива, приоритет, наблюдаемые
  потоки, границы наблюдения, следующий запрос данных, кластер.
- Пути от исходных клиентов в трёх режимах: структура, «позже по датам», «тот же день возможен». Для режимов
  с датами показан пример пути с датой и суммой каждого шага и оговорка, что достижимость не доказывает
  движение тех же денег.
- Справка для проверки в Markdown (`spravka-<gid>.md`) из фактов выбранного счёта.
- Стрелки «Назад» и «Вперёд» по просмотренным счетам. Источник один — история браузера, поэтому стрелки
  совпадают с кнопками браузера и выключены на границах. Режим дат хранится вместе со счётом.
- Подробности (правило с порогами и обоснованием, все кандидаты роли, состав приоритета, ограничения
  данных, сведения о выборке) раскрываются по запросу, чтобы на экране оставались счёт, карта и главное.

## Проверки

| ID | Что проверяется | Тест |
|---|---|---|
| `WEB-SCHEMA` | Файл анализа проверяется при загрузке; чужая версия схемы и неполный файл отклоняются | `tests/schema.test.ts` |
| `WEB-GID-EXACT` | `gid`, записанный числом, отклоняет файл целиком; 18-значные номера вне точных чисел JavaScript | `tests/schema.test.ts` |
| `WEB-SEARCH` | Открывается только точный `gid`; `gid + 1`, округлённое и экспоненциальное число не подменяют счёт | `tests/search.test.ts` |
| `WEB-MAP-CYCLE` | Встречный поток и цикл длиной 3 через счёт находятся и рисуются как «возвратный поток» | `tests/neighborhood.test.ts` |
| `WEB-MAP-FOLD` | Больше 10 контрагентов сворачиваются в «ещё N» с точной суммой скрытых | `tests/neighborhood.test.ts` |
| `WEB-MAP-ISOLATE` | Счёт без переводов показан с пояснением, а не пустым | `tests/neighborhood.test.ts` |
| `WEB-MAP-BOUNDARY` | У счёта на границе выборки нет получателей и есть отметка о границе | `tests/neighborhood.test.ts` |
| `WEB-BRIEF` | Справка содержит точный gid, роль, альтернативу, даты пути, оговорку и не содержит слов о виновности | `tests/brief.test.ts` |
| `WEB-LINK` | Ссылка `#gid=…&mode=…` читается и пишется без потерь; без режима — режим по умолчанию | `tests/hash.test.ts` |
| `WEB-REAL` | На настоящем файле: каждый из 2 248 счетов ищется точно, окрестность и справка строятся | `tests/real-data.test.ts` |

Запуск: `npm test`; на настоящем файле — `WORKBENCH_REAL=../out/analysis.json npm test`.
Состояния экрана для браузерной проверки перечислены в `surface.manifest.json` (двенадцать состояний,
переход панели поиска, два сценария), например:
`node verify.mjs http://127.0.0.1:8765/ --manifest web/surface.manifest.json`.
Параметр `?analysis=/out/<файл>.json` загружает другой файл из `/out/`, чтобы показать состояние
«файл не найден»; адреса вне `/out/` игнорируются.

## Точность идентификаторов

Все 18-значные `gid` больше `Number.MAX_SAFE_INTEGER`. В браузере они остаются строками: нет ни одного
`Number()` или `parseInt()` над идентификатором, сравнение и сортировка идут по строкам. Файл, в котором
`gid`, `src`, `dst` или `seed_gid` записан числом, отклоняется целиком с объяснением: точность такого
значения уже потеряна при разборе JSON. Это проверяют тесты `[WEB-GID-EXACT]` и `[WEB-SEARCH]`.

## Синтетический пример

`fixtures/analysis.json` создаёт `npm run fixture` (`fixtures/build-fixture.mjs`). Это придуманные счета с
префиксом `999`, собранные так, чтобы на экране встретилось каждое состояние: свёртка, циклы, граница
выборки, изолированный клиент, путь только «в тот же день». В файле есть поле
`fixture.synthetic = true`. Интерфейс и справка всегда помечают такие данные как синтетические.
Это не результат анализа выборки организаторов.

## Устройство

| Каталог | Назначение |
|---|---|
| `src/data/` | Контракт файла и его проверка (`schema.ts`), индекс (`graph.ts`), поиск, окрестность, форматирование, справка |
| `src/map/` | Раскладка окрестности и камера карты; часть перенесена из Command Center (см. ниже) |
| `src/ui/` | Панели: очередь, поиск, карта и список, основания, кластер, состояние загрузки |
| `src/app/` | Корень, загрузка файла, состояние в адресе, место для помощника |
| `src/styles/` | Токены, базовые стили, компоненты, виды, адаптивный слой (одна точка входа `index.css`) |

## Помощник

`src/app/AssistantSlot.tsx` подключает `src/features/assistant/index.tsx`, если такой файл есть. Эту часть
разрабатывают отдельно. Модуль экспортирует `AssistantPanel` со свойствами
`{selection: string[], onSelectNode(gid), className?}`. Счёт, выбранный из ответа помощника, открывается
через ту же проверку, что и поиск. Пока модуля нет, место пустое: ручной сценарий от помощника не зависит.
