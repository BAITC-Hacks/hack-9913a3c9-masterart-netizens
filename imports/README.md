# imports — загрузка нового набора данных

Позволяет проанализировать новый набор данных без командной строки: пользователь выбирает три
файла в интерфейсе, сервер проверяет их тем же загрузчиком, что и данные кейса
(`backend.io.load_dataset`), строит анализ тем же `build_analysis` и заменяет выгрузки в `out/`.

## Что поддерживается

Ровно одна схема — схема данных кейса. Нужны все три файла с точными именами:

| Файл | Обязательные столбцы |
|---|---|
| `nodes.parquet` | `gid` (целое int64), `depth`, `is_seed` |
| `edges.parquet` | `src`, `dst` (целые int64), `sum_kzt`, `n_tx`, `depth` |
| `transactions.parquet` | `src`, `dst` (целые int64), `date` (ГГГГ-ММ-ДД), `sum_kzt` |

Лишние столбцы игнорируются. Правила строк те же, что в командной строке: уникальные `gid`,
рёбра только между известными счетами, суммы рёбер совпадают с транзакциями, суммы с точностью
до тиына. **Подключение произвольной базы данных, CSV, Excel и других схем не поддерживается.**
Для них сначала нужна согласованная схема и доступ к данным.

## Пределы

| Что | Предел | Почему |
|---|---|---|
| Один файл | 4 МиБ | файлы кейса занимают 12–41 КБ |
| Три файла вместе | 8 МиБ | |
| Тело запроса | 12 МиБ | base64 увеличивает объём на треть |
| Строк | nodes 25 000 · edges 50 000 · transactions 100 000 | в кейсе 2 248 · 3 119 · 4 840; анализ на них идёт около 1 с |
| После распаковки | 64 МиБ на файл | защита от «сжатой бомбы» |

Размеры и число строк проверяются по метаданным parquet до чтения таблиц.

## API

`POST /api/import`, `Content-Type: application/json`:

```json
{"files": {"nodes.parquet": "<base64>", "edges.parquet": "<base64>", "transactions.parquet": "<base64>"}}
```

- `200` — `{"ok": true, "dataset": {"input_sha256", "n_nodes", "n_edges", "n_transactions", "n_seed", "n_clusters", "period_start", "period_end", "input_checks", "pipeline_seconds", "files", "outputs", ...}}`.
  `input_sha256` совпадает с контрольной суммой, которую даёт командная строка на тех же файлах.
- `400` — неверный запрос: не JSON, лишние или недостающие файлы, повтор поля, неверный base64.
- `409` — уже идёт другой импорт.
- `413` — превышен предел размера или числа строк.
- `422` — файлы не проходят проверку данных; сообщение на русском называет причину.

## Безопасность и сохранность

- Имена файлов берутся только из закрытого списка, поэтому путь не выходит за временный каталог.
- Файлы читаются только как parquet; никакого pickle, SQL или выполнения кода.
- Прежние выгрузки заменяются только после полного успеха проверки и анализа. При ошибке они
  остаются нетронутыми, а неудача записывается в `last_attempt.json`, как в командной строке.
- Каждый файл заменяется атомарно (`os.replace`), `analysis.json` — последним. Временные каталоги
  удаляются при любом исходе.
- Сервер слушает только 127.0.0.1; данные никуда не отправляются.
