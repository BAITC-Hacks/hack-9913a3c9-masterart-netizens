# Реестр функций

Каждая строка связывает требование кейса с функцией, проверкой и её состоянием. Идентификатор
функции стоит в названии теста, поэтому упавший тест сразу называет сломанную функцию.

**Как воспроизвести все проверки** (после установки зависимостей из README, раздел 7):

```bash
FINANCE_DATA=data FINANCE_DATA_DIR=data python -m unittest discover -s tests -v
cd web && WORKBENCH_REAL=../out/analysis.json npm test
```

Состояния: **готово** — функция в основной ветке и её проверка проходит; **в интеграции** — код
написан и проверен отдельно, но ещё не объединён с основной веткой; **запланировано** — кода нет.
