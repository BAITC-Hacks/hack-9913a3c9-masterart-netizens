# Помощник по графу

Помощник читает готовый `analysis.json` и возвращает проверяемые факты. Языковая модель
выбирает одну ограниченную операцию; суммы, точные идентификаторы, счётчики и формулировки
ответа выводит Python из результата этой операции. Свободный текст модели не публикуется.

```python
from assistant import answer, load_config

# Конфигурация читается только на сервере; путь к файлу указывается явно.
config = load_config()  # OPENAI_API_KEY и OPENAI_MODEL из окружения
result = answer(question, selection, analysis, **config)
```

`selection` — список точных десятичных строк `gid`. `analysis` — объект схемы
`finance-workbench/v1`. Нельзя передавать идентификаторы числами из JavaScript.
Модель по умолчанию — `gpt-6-astra`; её доступность зависит от ключа сервера.
`load_config(".env")` читает только два известных параметра, не исполняет shell и не ищет
файлы самостоятельно. Окружение имеет приоритет. Секреты нельзя возвращать в HTTP-ответе.

Шаблон серверной конфигурации содержит только пустые значения:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=
```

Результат имеет поля:

| Поле | Содержание |
|---|---|
| `answer_md` | Русский Markdown, построенный кодом из результата операции |
| `answer_rich_md` | Дополнительное представление тех же фактов: таблицы очереди, сравнения и карточки; Mermaid для проверенного пути с датами. Обычный `answer_md` остаётся запасным вариантом |
| `nodes` | Точные строки `gid`, доступные для выбора в интерфейсе |
| `intent`, `args` | Вид запроса и проверенные аргументы |
| `parser` | `openai`: модель выбрала операцию и завершила цикл; `rules`: локальный разбор; `none`: отказ или ошибка входа |
| `warnings` | Ограничения и явное указание отсутствия модели или сбоя API |
| `citations` | `{source:"/out/analysis.json", pointer, label, gid?}`; `pointer` — JSON Pointer к исходному факту |
| `tool_trace` | Только проверенные `{name,args,result}`; без ключа, текста модели и её рассуждений |
| `model` | Имя модели только после успешного цикла API |
| `navigation` | Необязательный проверенный переход: `view` (`account`, `map`, `cluster`, `queue`, `saved`), точный `gid` или `null`, `cluster_id` или `null` |

Ссылки на счета имеют вид `?gid=<точная строка>`; интерфейс может перехватывать их для выбора
узла. В `nodes` всегда строки. Отрисовщик Markdown должен оставлять HTML выключенным.

Операции: карточка счёта, входящие/исходящие рёбра, приоритет проверки, кластеры,
достижимость хотя бы от `k` выбранных источников, временной путь, границы наблюдения,
сравнение 2–5 счетов с основаниями очереди и следующим запросом данных. При равенстве
приоритета сравнение явно говорит, что этот показатель не задаёт предпочтение.
`get_insights(section,gid,limit)` читает девять уже рассчитанных разделов паттернов;
новой аналитики эта операция не запускает. Лимит — 10 сохранённых примеров или сценариев.
При поиске по счёту отсутствие его среди ограниченных примеров не означает отсутствие паттерна;
отметки полного расчёта счёта показываются отдельно. Сценарии устойчивости доступны для всей
выборки: первыми идут удаление по приоритету, по обороту и случайная опора при одинаковом N;
случайный результат подписан как среднее, а расчёт — как сценарий, не прогноз блокировки.
Пустой список источников означает всех исходных клиентов. Сам источник исключается из своего
счётчика достижимости. Отображается до 30 результатов с общим числом найденных; источников
может быть до 100. Результаты одного запроса детерминированы; выбор операции моделью — нет.

Временные режимы:

- `static`: направленный путь без учёта дат.
- `strict`: каждый следующий перевод только в более поздний день; весь день обрабатывается пакетом.
- `same_day`: возможный порядок переводов внутри дня, до замыкания дневного графа.

Без ключа поддерживаются явные запросы: «объясни выбранный счёт», «входящие связи», «топ 10»,
«кластер 0», «достижимы хотя бы от 2 выбранных счетов строго по дням», «путь по датам»,
«каких данных не хватает». Это разбор по правилам, а не работа языковой модели.
Непонятный вопрос возвращает справку. Сбой API явно помечается и запускает тот же локальный разбор.

Интеграционный сервер вызывает `answer` из `POST /api/assistant` с `{question,selection}`;
допустимы также `model`, `effort`, `history`, `dataset_fingerprint`. Модель и уровень проверяются
по единому серверному списку в `config.py`. `api_key`, `analysis` и `transport` из тела
HTTP-запроса принимать нельзя.
Сервер отвечает за доступ с loopback, проверку Origin, размер тела и ограничение параллельных запросов.
Помощник сам не открывает файлов и сети по инструкции пользователя или модели.

`GET /api/assistant/options` получает настройки через `assistant_options(analysis, model=…)`:
модели, совместимые уровни, значения по умолчанию, `history_limits` и отпечаток набора данных.
История содержит не больше шести `{question,selection,result_gids}`: по 1 000 символов вопроса
и 100 точных идентификаторов в каждом списке. Полный текст прежнего ответа не принимается
как источник фактов. «Почему второй?» повторно запрашивает карточку второго счёта предыдущего
результата, даже если на карте сейчас выбран другой. Явный gid в новом вопросе имеет приоритет.
Изменение любых данных, периода или правил меняет отпечаток; продолжение старого диалога
отклоняется до вызова модели. Полная видимая история и её сохранение принадлежат интерфейсу.

GPT-6 Astra: `low`, `medium`, `high`, `xhigh`, `max`; Sol и Luna дополнительно допускают `none`.
По умолчанию Astra/medium. См. [официальную документацию уровней рассуждения](https://developers.openai.com/api/docs/guides/reasoning#reasoning-effort).

Внешний запрос направляется только в `https://api.openai.com/v1/responses`; перенаправления
и прокси окружения отключены. Передаются вопрос, выбранные `gid`, номера их кластеров и
ограниченный результат выбранной операции. Весь граф не отправляется. `store:false` не заменяет
условия обработки данных провайдером. Для локального режима передайте `api_key=""`.
Необходима сеть только для необязательной модели; дополнительных Python-зависимостей нет.

Схемы функций строгие: все поля обязательны, лишние запрещены. Код повторно проверяет
идентификаторы, диапазоны, перечисления, дубликаты и соответствие счетов вопросу/выделению.
Не более двух запросов API, по 30 секунд на запрос, без автоматических повторов. При `store:false`
в продолжение переносятся `reasoning.encrypted_content`, остальные элементы `output` и
`function_call_output` с исходным `call_id`, согласно
[документации Responses function calling](https://developers.openai.com/api/docs/guides/function-calling).

Проверка без сети и ключа:

```sh
python -m unittest discover -s tests -p 'test_assistant.py' -v
```

Для проверки на готовом официальном результате задайте `ASSISTANT_ANALYSIS_PATH` — путь
к `analysis.json`. Без него проверка официальных данных явно пропускается; синтетические
и транспортные проверки выполняются всегда. Тесты не обращаются к реальному API.

Ограничения: нет размеченных эталонных ролей, личных атрибутов, денежных остатков и
внутридневного порядка. Достижимость не доказывает движение одних и тех же средств.
Связи на границе выборки неполны. Разбор по правилам не понимает произвольный язык.
Поиск не проверен на миллионном графе; размер снимка ограничен 50 тысячами узлов,
200 тысячами рёбер и 300 тысячами транзакций. Живой API и интеграция с браузером
проверяются отдельно от тестов с подменённым транспортом.

## Читаемое объяснение

Системная инструкция выбирает предмет и операцию, учитывает контекст и разделяет
приоритет, опору роли и ограничения наблюдения. Сама инструкция не гарантирует точность:
аргументы повторно проверяются кодом, а текст, таблицы и схемы собираются из результата.
Неподтверждённая проза модели не становится доказательством.

Для расширенного отображения интерфейс может выбрать `answer_rich_md`: сравнение показывает
суммы рядом, карточка — таблицу признаков, путь — схему и таблицу переводов с датами.
Идентификаторы в схемах — точные строки; служебные имена узлов имеют вид `n0`, `n1`.
В схеме не больше 12 шагов; усечение явно подписано, полная цепочка остаётся в основаниях.
У Markdown должны быть выключены произвольный HTML и внешние изображения; ссылки
на счета разрешены только для точных `gid` из текущего ответа. Mermaid работает
в строгом режиме без внешних действий. До подключения такого отрисовщика используется `answer_md`.

## Переходы по интерфейсу

Явные просьбы «открой счёт», «покажи на карте», «открой кластер», «перейди в очередь»
и «открой сохранённые» доступны через `navigate_view`. Сервер проверяет существование счёта,
кластера и соответствие вопросу. Свободные URL, код и неизвестные разделы не принимаются.
Обычное объяснение не разрешает модели самостоятельно переключать экран.

`navigation` — намерение для интерфейса, а не доказательство совершённого перехода.
Клиент применяет его только к свежему ответу после проверки контекста запроса и отпечатка
данных; открытие старого разговора никогда не повторяет действия. Сохранение счёта,
удаление данных и построение отчёта этим инструментом не выполняются.
